# 关于claude code的记忆系统


## 两种记忆系统

- CLAUDE.md
- 自动记忆提取系统

> CLAUDE.md 这个记忆是由用户进行书写的，而自动记忆提取系统会在内部通过一个独立的agent(forked agent)进行自动提取。

## CLAUDE.md文件

cc的记忆 / 指令内容会从多个来源加载，并按一定顺序叠加，主要可概括为以下 4 类来源：

1. 受管控/企业级下发的全局指令(公司进行配置)
2. 所有项目的私人全局指令，即 ~/.claude/CLAUDE.md
3. 项目记忆，即：项目根目录下的 CLAUDE.md、.claude/CLAUDE.md 和 .claude/rules/*.md 这些提交到git仓库的记忆文件
4. 本地记忆文件，即：项目根目录下的 CLAUDE.local.md 这些不提交到git仓库的记忆文件

这些来源会按 1 -> 2 -> 3 -> 4 的顺序加载；通常越靠后的来源越贴近当前用户和当前项目，因此在实际使用时优先级也更高


## 自动记忆提取系统

> 自动记忆提取系统主要包含两类记忆提取机制：长期记忆提取和会话记忆提取


### 长期记忆

主要入口之一函数为：`src\services\extractMemories\extractMemories.ts` 中的 `runExtraction` 函数

执行过程为：

1. 调用 `countModelVisibleMessagesSince` 函数统计自上次游标位置以来新增了多少条“模型可见消息”
2. 调用 `hasMemoryWritesSince` 函数，查看有没有出现过对 auto-memory 路径的 Write / Edit 工具调用，这样来确保这些新增信息没有在主agent中被收集过
3. 筛出、排序后取最多 200 个记忆文件中的 `frontmatter`,形成一个 `${tag}${m.filename} (${ts}): ${m.description}` 这样的格式
4. 构建提示词，在构建这个提示词中会根据你是否开启了团队记忆能力，构建出不同的提示词，大致包括：
    - 如何保存 memory 文件
    - 读取最近的对话内容，检查现有的 memory 文件
    - 判断应该更新已有 memory，还是新增一条 memory 
    - 如果用户明确让你记住某件事，就立刻按最合适的类型将其保存下来；如果用户要求你忘记某件  事，就找到相关条目并将其删除。
    - 四类分类说明。
    - 不应该被保存到记忆文件的提示词。

    团队记忆开启时，提示词会增加团队共享相关约束，尤其是敏感信息禁止写入共享记忆；同时分类说明和保存策略也会随模式调整。
    
    如果用户开启了 `MEMORY.md 索引维护的功能` 会在记忆文件夹中在维护一个 `MEMORY.md` 文件不存储任何记忆，只是把新加/修改的记忆维护一个索引在里面，格式为：`[Title](file.md)` 每个索  引长度不超过150 个字，在加载到系统提示词中，只会加载前200个索引，所以这个文件要保持整洁


5. 调用 `runForkedAgent` 执行记忆提取与保存流程；其底层执行依赖 `queryLoop`这个查询主循环生成器。这里先不展开其细节，后续再单独分析。

#### 自动记忆文件截断机制

> 在加载自动记忆文件的时候，cc内部会对自动记忆文件进行一个截断

主要函数之一为：`src\memdir\memdir.ts` 中的 `truncateEntrypointContent` 函数

```ts
export const MAX_ENTRYPOINT_LINES = 200

export function truncateEntrypointContent(raw: string): EntrypointTruncation {
  const trimmed = raw.trim()
  const contentLines = trimmed.split('\n')
  const lineCount = contentLines.length
  const byteCount = trimmed.length

  const wasLineTruncated = lineCount > MAX_ENTRYPOINT_LINES

  const wasByteTruncated = byteCount > MAX_ENTRYPOINT_BYTES

  let truncated = wasLineTruncated
    ? contentLines.slice(0, MAX_ENTRYPOINT_LINES).join('\n')
    : trimmed

  if (truncated.length > MAX_ENTRYPOINT_BYTES) {
    const cutAt = truncated.lastIndexOf('\n', MAX_ENTRYPOINT_BYTES)
    truncated = truncated.slice(0, cutAt > 0 ? cutAt : MAX_ENTRYPOINT_BYTES)
  }

  const reason =
    wasByteTruncated && !wasLineTruncated
      ? `${formatFileSize(byteCount)} (limit: ${formatFileSize(MAX_ENTRYPOINT_BYTES)}) — index entries are too long`
      : wasLineTruncated && !wasByteTruncated
        ? `${lineCount} lines (limit: ${MAX_ENTRYPOINT_LINES})`
        : `${lineCount} lines and ${formatFileSize(byteCount)}`

  return {
    content:
      truncated +
      `\n\n> WARNING: ${ENTRYPOINT_NAME} is ${reason}. Only part of it was loaded. Keep index entries to one line under ~200 chars; move detail into topic files.`,
    lineCount,
    byteCount,
    wasLineTruncated,
    wasByteTruncated,
  }
}
```

#### 工具限制

提取记忆agent的工具权限定义是由 `src\services\extractMemories\extractMemories.ts` 中的 `createAutoMemCanUseTool` 函数定义的，本函数中 `Read` / `Grep` / `Glob` 可以不限范围使用，而 `Bash` 只允许执行只读命令，`Edit` / `Write` 只能作用在 auto-memory 目录内部的文件路径上


### 会话记忆

主要入口之一函数为：`src\services\SessionMemory\sessionMemory.ts` 中的 `extractSessionMemory` 函数

执行过程为：

1. 调用 `shouldExtractMemory` 函数，判断当前消息列表是否满足记忆提取的触发条件，判断条件为：(当前的token数是大于等于更新的最小token阈值(5000) && 工具调用次数大于等于最小调用次数(3次) ) || (当前的token数是大于等于更新的最小token阈值(5000) && 最近一轮没有发生工具调用)

2. 为工具上下文创建隔离环境，避免影响父级缓存
3. 确定 session memory 文件路径，并准备当前文件内容；若文件尚未初始化，则按模板创建并纳入后续读取/编辑流程
4. 构建一个session 记忆更新提示词。这个提示词可以让用户自定义，如果用户没有进行自定义的提示词则使用默认提示词，默认提示词如下：
   ```txt
     重要：这条消息以及这些说明都不是实际用户对话的一部分。不要在笔记内容中提及“记笔记”“会话笔记提取”或这些更新说明。
    请基于上方的用户对话内容（不包括这条记笔记说明消息，也不包括 system prompt、claude.md 条目或任何过去的会话摘要），更──
     session notes 文件。
    文件 {{notesPath}} 已经为你读取好了。它当前内容如下：
    <current_notes_content>
    {{currentNotes}}
    </current_notes_content>
    你唯一的任务就是使用 Edit 工具更新这个 notes 文件，然后停止。你可以进行多次编辑（按需更新每个 section）——所有 Edit
    工具调用都必须在同一条消息中并行发出。不要调用任何其他工具。
    编辑时必须遵守以下关键规则：
    - 文件必须严格保持原有结构，所有 section、标题和斜体说明都必须完整保留
    -- 绝不要修改、删除或新增 section 标题（即那些以 `#` 开头的行，例如 `# Task specification`）
    -- 绝不要修改或删除斜体的 _section description_ 行（它们是每个标题后面紧跟着的斜体说明行，以下划线开头并以下划线结尾
    -- 这些斜体 _section descriptions_ 是模板说明，必须原封不动地保留——它们用于指导每个 section 应该写什么内容
    -- 你只能更新每个现有 section 中、位于这些斜体说明行下面的实际内容
    -- 不要在现有结构之外新增任何 section、总结或信息
    - 不要在笔记中提及这次记笔记流程或这些说明
    - 如果某个 section 没有实质性的新内容，可以不更新。不要添加像 “No info yet” 这样的凑数内容；如果合适，就让这些 section
     保持空白或不改动
    - 每个 section 都要写得详细、信息密度高——尽量包含具体信息，例如文件路径、函数名、错误信息、确切命令、技术细节等
    - 对于 “Key results” 一栏，要包含用户要求的完整、精确输出（例如完整表格、完整答案等）
    - 不要写入那些已经存在于上下文所包含的 CLAUDE.md 文件里的信息
    - 每个 section 尽量控制在约 ${MAX_SECTION_LENGTH} 个 token/词以内——如果某个 section
    接近这个上限，就压缩精简掉不那么重要的细节，同时保留最关键的信息
    - 聚焦于可执行、具体的信息，这些信息应能帮助别人理解或复现对话中讨论过的工作
    - 重要：一定要更新 “Current State” 一栏，使其反映最近一次工作的最新状态——这对 compaction 之后保持连续性至关重要
    请使用 Edit 工具，并将 `file_path` 设为：{{notesPath}}
    结构保留提醒：
    每个 section 都有两个必须完全保留的部分，且必须与当前文件中的内容保持完全一致：
    1. section 标题（以 `#` 开头的那一行）
    2. 斜体说明行（紧跟在标题后面的那行 _斜体文本_ —— 这是模板说明）
    你只能更新这两行保留内容之后的实际正文内容。那些以下划线开头和结尾的斜体说明行属于模板结构的一部分，不是可以编辑或删
    的正文内容。

    记住：并行使用 Edit 工具，然后立即停止。编辑完成后不要继续。只能写入来自真实用户对话的内容，绝不能从这些记笔记说明中
    取内容。不要删除或修改 section 标题，也不要修改斜体的 _section descriptions_。
   ```
5. 调用 `runForkedAgent` 执行记忆提取与保存流程；其底层执行依赖 `queryLoop`这个查询主循环生成器。这里先不展开其细节，后续再单独分析。


#### 工具限制

提取记忆agent的工具限制：由 `src\services\SessionMemory\sessionMemory.ts` 中的 `createMemoryFileCanUseTool` 函数来提供，保证了它只允许特定编辑工具，只能对那个精确的 memory 文件执行 Edit。


### 会话记忆和长期记忆区别：

- `extractMemories.ts` 更偏向“长期沉淀”
- `sessionMemory.ts` 更偏向“当前会话摘要”或“会话压缩辅助信息”

也就是说，会话记忆不是同一个概念层级下的 durable memory store，而更像当前会话过程中的辅助记忆文件。

## 记忆加载

当需要进行记忆加载的时候，cc会调用 `src\utils\claudemd.ts` 中的 `getMemoryFiles` 函数获取到所有的记忆文件，然后使用 `getClaudeMds` 进行提示词的拼接


## 团队记忆的远端同步层

> 这个同步层有一个 `isUsingOAuth` 校验，你必须是官方的baseurl地址才可以使用，如果不是，则不能使用

核心文件为：`src\services\teamMemorySync\index.ts`

- pushTeamMemory：本地 team memory 文件推送到服务端，内部通过 batchDeltaByBytes(贪心算法)，把要上传的变更内容拆成多个 PUT 请求包，每个包尽量不要超过最大大小限制
- pullTeamMemory：从服务端同步拉取 team memory 到本地目录。
