# 前端工具执行实现方案

## 概述

本文档说明如何实现前端工具执行机制：当 AI 需要调用前端传入的工具时，不在后端直接执行，而是通知前端执行，并等待前端返回结果后继续 AI 流程。

## 问题背景

在当前项目中，前端可以动态传入工具定义（通过 AG-UI 协议）：

```typescript
// 前端传入的工具定义
{
  tools: [
    {
      name: 'getUserInfo',
      description: '获取用户信息',
      parameters: { /* JSON Schema */ }
    }
  ]
}
```

这些工具的实际执行逻辑在前端（例如访问浏览器 LocalStorage、操作 DOM、调用前端特有的 API 等），后端无法直接执行。

因此需要一个机制：
1. AI 决定调用工具时，通知前端
2. 前端执行工具并返回结果
3. 后端继续 AI 流程

## 方案选择

### 可选方案对比

| 方案 | 实现复杂度 | 连接方式 | 优势 | 劣势 |
|------|----------|---------|------|------|
| LangGraph interrupt | 高 | 两次 HTTP 请求 | 可靠、支持服务重启 | 实现复杂、需要状态管理 |
| Promise + 长连接 | 中 | 单次 SSE 连接 | 实现简单、用户体验好 | 需要保持长连接 |
| 分两次对话 | 低 | 两次 HTTP 请求 | 最简单 | 用户体验差 |

### 选择的方案：Promise + 长连接

**核心思路：**
- 在工具的 `func` 中创建一个 pending Promise
- 发送 `toolStart` 事件给前端
- Promise 阻塞等待前端返回结果
- 前端通过新的 API 提交结果，resolve Promise
- LangGraph 继续执行

**优势：**
- 单次 SSE 连接完成整个流程
- 用户体验流畅
- 实现相对简单

**劣势：**
- 需要保持 HTTP 长连接
- 需要处理超时情况

## 实现原理

### 执行流程图

```
用户发送消息
    ↓
AI 决定调用工具
    ↓
创建 pending Promise ←─────┐
    ↓                      │
发送 toolStart 事件        │ 等待
    ↓                      │
前端收到事件               │
    ↓                      │
前端执行工具               │
    ↓                      │
POST /tool-result ─────────┘
    ↓
Promise resolve
    ↓
LangGraph 继续执行
    ↓
AI 生成最终回复
```

### 关键机制

#### 1. Promise 阻塞机制

在工具的 `func` 中创建 Promise，LangGraph 会等待 Promise resolve：

```typescript
func: async (input, config) => {
  const toolCallId = config.metadata.tool_call_id;

  // 这个 Promise 会阻塞，直到前端提交结果
  const result = await toolExecutionManager.waitForResult(toolCallId);

  return result;
}
```

#### 2. 工具调用 ID 映射

使用 `tool_call_id` 作为 key，管理多个并发的工具调用：

```typescript
class ToolExecutionManager {
  private pending = new Map<string, {
    resolve: (result: string) => void;
    reject: (error: Error) => void;
  }>();
}
```

#### 3. SSE 连接保持

整个流程在单次 SSE 连接中完成：

```
客户端 ──────── SSE 连接 ────────> 服务端
   ↑                                  ↓
   │                            toolStart 事件
   │                                  ↓
   │                            Promise 等待...
   │                                  ↓
   └──── POST /tool-result ──────────┘
                                      ↓
                              Promise resolve
                                      ↓
                              继续生成回复
```

## 实现步骤

### 步骤 1：创建工具执行管理器

**文件位置：** `src/ai/utils/toolExecutionManager.ts`

**核心功能：**

```typescript
export class ToolExecutionManager {
  private pending = new Map<string, {
    resolve: (result: string) => void;
    reject: (error: Error) => void;
  }>();

  /**
   * 创建一个等待前端执行的 Promise
   * @param toolCallId 工具调用 ID
   * @param timeout 超时时间（毫秒），默认 60000
   */
  waitForResult(toolCallId: string, timeout = 60000): Promise<string> {
    return new Promise((resolve, reject) => {
      // 存储 resolve/reject 函数
      this.pending.set(toolCallId, { resolve, reject });

      // 设置超时
      const timer = setTimeout(() => {
        if (this.pending.has(toolCallId)) {
          this.pending.delete(toolCallId);
          reject(new Error(`Tool execution timeout: ${toolCallId}`));
        }
      }, timeout);

      // 清理定时器（当 Promise resolve/reject 时）
      const originalResolve = resolve;
      const originalReject = reject;

      this.pending.set(toolCallId, {
        resolve: (result: string) => {
          clearTimeout(timer);
          this.pending.delete(toolCallId);
          originalResolve(result);
        },
        reject: (error: Error) => {
          clearTimeout(timer);
          this.pending.delete(toolCallId);
          originalReject(error);
        }
      });
    });
  }

  /**
   * 提交工具执行结果
   * @param toolCallId 工具调用 ID
   * @param result 执行结果
   */
  submitResult(toolCallId: string, result: string): boolean {
    const pending = this.pending.get(toolCallId);
    if (pending) {
      pending.resolve(result);
      return true;
    }
    return false;
  }

  /**
   * 提交工具执行错误
   * @param toolCallId 工具调用 ID
   * @param error 错误信息
   */
  submitError(toolCallId: string, error: string): boolean {
    const pending = this.pending.get(toolCallId);
    if (pending) {
      pending.reject(new Error(error));
      return true;
    }
    return false;
  }

  /**
   * 检查是否有等待中的工具调用
   */
  hasPending(toolCallId: string): boolean {
    return this.pending.has(toolCallId);
  }
}

// 导出单例
export const toolExecutionManager = new ToolExecutionManager();
```

### 步骤 2：修改工具创建逻辑

**文件位置：** `src/ai/utils/adapters.ts:139-149`

**修改前：**

tools: tools.map(item => {

**修改后：**

```typescript
import { toolExecutionManager } from './toolExecutionManager';

tools: tools.map(item => {
  return new DynamicStructuredTool({
    name: item.toolName,
    description: item.toolDescription,
    schema: item.toolParams,
    func: async (input, config) => {
      // 获取工具调用 ID
      const toolCallId = config?.metadata?.tool_call_id;

      if (!toolCallId) {
        throw new Error('Missing tool_call_id in config');
      }

      // 等待前端执行工具并返回结果
      // 这个 Promise 会阻塞，直到前端调用 /tool-result API
      const result = await toolExecutionManager.waitForResult(toolCallId);

      return result;
    },
  });
})
```

### 步骤 3：修改事件输出，携带工具参数

**文件位置：** `src/ai/utils/adapters.ts` 的 `langChainStreamEventsOutputToUnifyOutput` 函数

**问题：** 前端需要知道工具的输入参数才能正确执行工具。

**解决方案：** 在 `toolStart` 事件中添加 `toolCallArgs` 字段。

**修改前：**

```typescript
else if (eventName === 'on_tool_start') {
  yield {
    event: 'toolStart',
    toolCallId: event.metadata.tool_call_id,
    toolCallName: event.metadata.tool_name,
  };
}
```

**修改后：**

```typescript
else if (eventName === 'on_tool_start') {
  yield {
    event: 'toolStart',
    toolCallId: event.metadata.tool_call_id,
    toolCallName: event.metadata.tool_name,
    toolCallArgs: event.data.input,  // 添加工具的输入参数
  };
}
```

**说明：**
- `event.data.input` 包含了 AI 传递给工具的参数
- 前端可以根据 `toolCallArgs` 知道应该传递什么参数给工具
- 例如：`{ city: "北京" }` 表示需要查询北京的天气

### 步骤 4：新增 API 接口

**文件位置：** `src/api/ai/aiChat.ts`

**新增路由：** `POST /api/ai/ai-chat/tool-result`

**实现代码：**

```typescript
import { toolExecutionManager } from '@/ai/utils/toolExecutionManager';

/**
 * 接收前端提交的工具执行结果
 */
router.post('/tool-result', async (req, res) => {
  try {
    const { toolCallId, result, error } = req.body;

    // 验证参数
    if (!toolCallId) {
      return res.status(400).json({
        success: false,
        message: 'Missing toolCallId'
      });
    }

    // 检查是否有等待中的工具调用
    if (!toolExecutionManager.hasPending(toolCallId)) {
      return res.status(404).json({
        success: false,
        message: 'Tool call not found or already completed'
      });
    }

    // 提交结果或错误
    if (error) {
      toolExecutionManager.submitError(toolCallId, error);
    } else {
      toolExecutionManager.submitResult(toolCallId, result);
    }

    res.json({ success: true });
  } catch (err) {
    console.error('Tool result submission error:', err);
    res.status(500).json({
      success: false,
      message: 'Internal server error'
    });
  }
});
```

**请求示例：**

```typescript
// 成功情况
POST /api/ai/ai-chat/tool-result
{
  "toolCallId": "call_abc123",
  "result": "{\"city\":\"北京\",\"weather\":\"晴\",\"temperature\":\"18-26℃\"}"
}

// 错误情况
POST /api/ai/ai-chat/tool-result
{
  "toolCallId": "call_abc123",
  "error": "Failed to fetch user info: Network error"
}
```

### 步骤 4：前端实现

**监听 toolStart 事件：**

```typescript
// 前端代码示例
eventSource.addEventListener('message', (event) => {
  const data = JSON.parse(event.data);

  if (data.event === 'toolStart') {
    const { toolCallId, toolCallName } = data;

    // 执行工具
    executeToolAndSubmitResult(toolCallId, toolCallName);
  }
});

async function executeToolAndSubmitResult(toolCallId: string, toolName: string) {
  try {
    // 根据工具名称执行对应的逻辑
    const result = await executeTool(toolName);

    // 提交结果给后端
    await fetch('/api/ai/ai-chat/tool-result', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        toolCallId,
        result: JSON.stringify(result)
      })
    });
  } catch (error) {
    // 提交错误给后端
    await fetch('/api/ai/ai-chat/tool-result', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        toolCallId,
        error: error.message
      })
    });
  }
}
```

## 完整流程示例

### 场景：用户询问天气

**1. 用户发送消息**

```
POST /api/ai/ai-chat/chat
{
  "messages": [
    { "role": "user", "content": "北京今天天气怎么样" }
  ],
  "tools": [
    {
      "name": "getWeather",
      "description": "获取天气信息",
      "parameters": { /* JSON Schema */ }
    }
  ],
  "threadId": "thread-123"
}
```

**2. 后端处理**

- LangGraph 执行，AI 决定调用 `getWeather` 工具
- 调用工具的 `func`，创建 pending Promise
- 发送 `toolStart` 事件给前端：

```json
{
  "event": "toolStart",
  "toolCallId": "call_abc123",
  "toolCallName": "getWeather"
}
```

- Promise 阻塞等待...
- SSE 连接保持打开

**3. 前端执行工具**

```typescript
// 前端收到 toolStart 事件
const result = await fetch('https://weather-api.com/beijing');
// { city: "北京", weather: "晴", temperature: "18-26℃" }
```

**4. 前端提交结果**

```
POST /api/ai/ai-chat/tool-result
{
  "toolCallId": "call_abc123",
  "result": "{\"city\":\"北京\",\"weather\":\"晴\",\"temperature\":\"18-26℃\"}"
}
```

**5. 后端继续执行**

- Promise resolve，返回工具结果
- LangGraph 继续执行
- AI 基于工具结果生成回复
- 发送 `messageChunk` 事件：

```json
{
  "event": "messageChunk",
  "message": "北京今天天气晴朗，气温 18-26℃，适合出行。",
  "messageId": "msg_xyz"
}
```

**6. 完成**

- 发送 `messageEnd` 和 `modelEnd` 事件
- 关闭 SSE 连接

## 注意事项

### 1. 超时处理

**问题：** 前端可能因为网络问题、用户取消等原因无法返回结果。

**解决方案：**
- 在 `waitForResult` 中设置超时（默认 60 秒）
- 超时后自动 reject Promise
- AI 可以捕获错误并告知用户

```typescript
try {
  const result = await toolExecutionManager.waitForResult(toolCallId, 60000);
  return result;
} catch (error) {
  // 超时或其他错误
  return JSON.stringify({
    error: true,
    message: error.message
  });
}
```

### 2. HTTP 连接超时

**问题：** SSE 连接可能因为长时间无数据而被中间代理或浏览器关闭。

**解决方案：**
- 设置合理的工具执行超时时间（不要太长）
- 或者定期发送心跳事件保持连接：

```typescript
// 每 30 秒发送一次心跳
const heartbeat = setInterval(() => {
  res.write(':\n\n');  // SSE 注释，保持连接
}, 30000);
```

### 3. 并发工具调用

**问题：** AI 可能同时调用多个工具。

**解决方案：**
- 使用 `toolCallId` 区分不同的工具调用
- Map 结构天然支持并发管理
- 每个工具调用独立等待和 resolve

### 4. 错误处理

**前端工具执行失败的处理：**

```typescript
// 前端提交错误
POST /tool-result
{
  "toolCallId": "call_abc123",
  "error": "Network error: Failed to fetch"
}

// 后端 Promise reject
// AI 可以决定：
// - 重试
// - 使用备用方案
// - 告知用户错误
```

### 5. 内存泄漏防护

**问题：** 如果 Promise 既没有 resolve 也没有 reject，会导致内存泄漏。

**解决方案：**
- 超时后自动清理
- 在 resolve/reject 时立即从 Map 中删除
- 定期清理过期的 pending 记录（可选）

### 6. 安全性考虑

**问题：** 恶意前端可能提交伪造的工具结果。

**解决方案：**
- 验证 `toolCallId` 的有效性
- 检查工具结果的格式
- 对敏感操作添加额外验证
- 考虑添加签名机制

## 与其他方案的对比

### 与 LangGraph interrupt 方案对比

| 特性 | Promise 方案 | interrupt 方案 |
|------|------------|---------------|
| HTTP 请求次数 | 1 次（SSE + 1 次 POST） | 2 次（两次完整请求） |
| 连接方式 | 长连接 | 短连接 |
| 状态管理 | 内存中的 Promise | checkpointer 持久化 |
| 服务重启 | ❌ 状态丢失 | ✅ 可恢复 |
| 实现复杂度 | 中 | 高 |
| 用户体验 | 流畅 | 略有延迟 |

### 适用场景

**Promise 方案适合：**
- 工具执行时间较短（< 1 分钟）
- 服务稳定，不频繁重启
- 追求用户体验流畅度

**interrupt 方案适合：**
- 工具执行时间较长
- 需要高可靠性
- 服务可能重启

## 总结

使用 Promise + 长连接方案实现前端工具执行：

**核心机制：**
- ✅ 在工具 `func` 中创建 pending Promise
- ✅ 发送 `toolStart` 事件通知前端
- ✅ 前端执行工具后通过 API 提交结果
- ✅ Promise resolve，LangGraph 继续执行

**优势：**
- 单次 SSE 连接，用户体验流畅
- 实现相对简单
- 支持并发工具调用

**注意事项：**
- 需要处理超时情况
- 需要保持 HTTP 长连接
- 服务重启会导致状态丢失

**实现步骤：**
1. 创建 `ToolExecutionManager` 管理 pending Promise
2. 修改 `adapters.ts` 中的工具创建逻辑
3. 新增 `/tool-result` API 接收前端结果
4. 前端监听 `toolStart` 事件并执行工具
